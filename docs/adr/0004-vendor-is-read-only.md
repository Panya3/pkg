# `vendor/` อ่านเท่านั้น — ปรับแต่งผ่าน overlay หรือ patch set

ไฟล์ใต้ `vendor/` ไม่ถูกแก้ไม่ว่ากรณีใด เพราะ CI โคลนซอร์สเหล่านั้นจาก upstream ไม่ใช่จากเครื่องนักพัฒนา การแก้ที่ทำในนั้นจึงไม่มีทางไปถึง CI เลย — build จะพังตั้งแต่รอบแรก ขณะที่การแก้ที่เก็บไว้ฝั่ง hub (overlay หรือ patch set) ถูก commit ไปพร้อมกันและทำซ้ำได้เหมือนกันทุกเครื่อง

## Escalation

1. หา option/flag ของ upstream ที่ให้ผลที่ต้องการก่อน
2. ไม่มี → **overlay**: header ที่ hub เป็นเจ้าของเอง วางก่อน header ของ vendor ใน include path
3. overlay แทนไม่ได้ (ต้องแทรกกลางไฟล์) → **patch set**: ไฟล์ diff ใต้ `patches/` ลงกับสำเนาของ vendor ใน build tree ตอน configure แล้วชี้ `add_subdirectory` ไปที่สำเนานั้น
4. เป็นการแก้ระยะยาว → ค่อยพิจารณา fork พร้อมเหตุผล ไม่ใช่ทางเลือกแรก

## Consequences

- การ "แทรกโค้ด `#ifdef`/`#endif` ในไฟล์ `.h` ของ vendor" ต้องระบุเคสจริงเป็นราย ๆ ไปว่า overlay พอหรือต้องขึ้น patch set — ยังไม่มีอินสแตนซ์ใดถูกนำเข้าในรอบนี้ กลไกทั้งสองแบบถูกเตรียมไว้
- patch set ต้องเป็นไฟล์ที่ commit อยู่ฝั่ง hub เท่านั้น ไม่ใช่แก้ในซอร์สโดยตรง
